# Intelligence OS v0.6.1-alpha — Detailed Audit Report

Audit date: 2026-09-13 (JST)

## Scope

This audit examined the distributed source tree, unit tests, deterministic simulations, actual local HTTP runtime, Native Messaging bridge, release packaging rules, and external platform assumptions that materially affect the build.

The audit is intentionally stricter than a design review. Passing tests is not treated as proof of production readiness.

## Bottom line

**The core is executable, not merely conceptual.** Memory/Context, Executive routing, Skills contracts, local Verification/Knowledge Lifecycle, privacy gates, read-only Research ingestion, Native Messaging, and Outcome Learning all have executable code paths and automated tests.

However, this remains a **Developer Alpha**, not a production-grade autonomous cognitive system. Several important paths are either simulated or require credentials/platform environments that were not available in the audit environment.

## Material defects found and corrected during audit

### 1. Distribution simulation import failure

The HTTP simulation scripts could fail when executed from the extracted distribution root because `backend` was not added to `sys.path`.

**Correction:** simulation scripts now resolve the project backend themselves. A user no longer needs to manually inject `PYTHONPATH` for those HTTP simulations.

### 2. Verification scope overstatement

Running web Research previously risked making unrelated answer claims appear to have `current_web+local_memory` verification simply because a web search ran.

**Correction:** verification scope is now determined per Claim from the evidence actually used. Aggregate answer scope derives from claim scopes. The terminology is now `web_retrieval+local_memory`, because retrieval from the web does not itself prove that a source is newly published or true.

### 3. Artificial freshness from retrieval time

A web page without a known publication date could previously look fresh merely because it was fetched today.

**Correction:** missing publication date now yields neutral/unknown freshness (`0.5`). Retrieval time is not treated as publication time.

### 4. Low-authority pages could become `verified`

A direct statement on an arbitrary captured web page could previously cross the score threshold for `verified`.

**Correction:** `verified` now requires sufficiently direct support from higher-authority evidence (`source_quality >= 0.75`, `directness >= 0.55`, score threshold). Lower-authority direct support is labeled `supported`, not `verified`.

Important: this still means **verified against the evidence policy**, not absolute external truth.

### 5. Prompt-injection pattern miss

An earlier pattern could miss `Ignore all previous instructions`.

**Correction:** the detection regex was repaired and regression-tested. Retrieved pages remain untrusted evidence, never executable instructions.

### 6. Contradiction false positive

A source stating a new rule while mentioning an obsolete old rule could cause the new rule itself to be classified as contradictory because of nearby old numbers.

**Correction:** direct support is considered before heuristic opposition/numeric disagreement.

### 7. Claim duplication on reverification

Repeated verification could create duplicate Claim objects rather than a stable knowledge object with history.

**Correction:** equivalent Claims preserve a stable Claim ID; prior verdicts are stored in `claim_history`.

### 8. Google/private memory `all` mode leak

The global external-LLM mode `all` could previously override the intended local-only boundary for Google-derived memories.

**Correction:** Gmail, Google Drive, Google Calendar, and sensitive/highly-sensitive memories remain hard-local even in global `all` mode.

### 9. Research download memory bounding

Source size was checked after downloading the full response in memory.

**Correction:** downloads now stream with Content-Length pre-check plus a hard byte ceiling during streaming. Redirect targets are revalidated.

### 10. Credential-bearing research URLs

URLs containing embedded `username:password@host` credentials were not explicitly rejected.

**Correction:** credential-bearing URLs are rejected by the public-source URL validator.

### 11. Outcome "calibration error" was conceptually incorrect

`abs(confidence - match_score)` had been called calibration error even though `match_score` is a human-assessed degree of outcome match, not a Bernoulli/probabilistic observed event.

**Correction:** the system now exposes:

- `outcome_mismatch = 1 - match_score`
- `surprise_score = confidence × outcome_mismatch`

The legacy database column is retained only for migration compatibility. Proper calibration (for example Brier/log-loss style analysis) requires repeated objectively scored probabilistic forecasts and is not claimed here.

### 12. Accepted personal lessons had excessive factual authority

Human acceptance of a lesson was previously close to high-authority external evidence.

**Correction:** accepted lessons remain important personal Memory but have modest external factual authority (`0.55`). Human acceptance confirms a personal learning record, not universal truth.

### 13. Native-host response-size boundary

Chrome Native Messaging limits host-to-Chrome messages to 1 MiB.

**Correction:** Native Host now enforces a 1 MiB output ceiling.

### 14. Windows Native Messaging binary-mode requirement

Chrome requires binary stdin/stdout on Windows; text mode can translate newlines and corrupt the length-prefixed Native Messaging protocol.

**Correction:** the native host now uses `msvcrt.setmode(..., os.O_BINARY)` on Windows and has a regression test guarding the behavior.

### 15. Frozen Windows host token/config path

A PyInstaller one-file Native Host cannot safely infer the source-tree data path from `__file__` after freezing.

**Correction:** installation writes `~/.intelligence-os/native-host/config.json` containing the intended local token path and Core origin. The host reads that runtime config.

### 16. Token logging

The Core had previously displayed a raw local API token in startup output.

**Correction:** startup logs no longer print the token. On loopback, the token is available from `/setup` for local bootstrap only.

## Externally fact-checked platform assumptions

### OpenAI Responses API web search

Current OpenAI API reference confirms that Responses supports built-in web search and that `web_search_call.action.sources` can be included. Current schema also exposes a `web_search` tool type.

**Audit status:** API design is consistent with the official current schema. **A real billed OpenAI web-search request was not executed in this audit environment** because no project API key / usable installed OpenAI SDK environment was available.

### Chrome Native Messaging

Current Chrome documentation confirms:

- host communication uses stdin/stdout with a 32-bit length prefix,
- `allowed_origins` cannot use wildcards,
- host-to-Chrome messages have a 1 MiB maximum,
- messages sent to the host are limited to 64 MiB in current extension documentation,
- Windows hosts need binary I/O mode.

The implementation now conforms to these material protocol constraints.

### Google OAuth scopes

Current Google documentation confirms that `drive.readonly` and `gmail.readonly` are **Restricted** scopes. Public production apps using restricted scopes require verification; server storage/transmission of restricted-scope data can trigger a security-assessment requirement. `drive.file` is the narrower recommended per-file scope for many use cases.

**Audit status:** scope policy claims are fact-checked. Live OAuth consent/login and real Gmail/Drive synchronization were **not** executed because user credentials/OAuth client secrets were intentionally unavailable.

## What is genuinely implemented vs still mostly architectural

### Executable today

- local persistent Memory and FTS5 retrieval
- optional embedding rerank path (when configured)
- source-key dedup/upsert
- Executive deterministic routing
- Skill contracts injected into reasoning
- local/external data boundary
- current-source Research orchestration and provenance ingestion
- local evidence classification
- Claim/Evidence/Contradiction/Supersession lifecycle
- explicit human correction/supersession
- audit records
- explicit Human Approval boundary for consequential actions
- Outcome/Decision/Expectation records
- human-gated lesson promotion
- Native Messaging bridge + loopback fallback

### Partially implemented

- **Executive:** deterministic heuristic router, not a general planner.
- **Skills:** Research/Verification/Reflection have executable machinery; several other skills remain mostly contracts/prompt procedures rather than independent state machines.
- **Evals:** LLM-evaluator path exists but was not live-called in this audit; heuristic fallback is intentionally weak and is not factual verification.
- **Attention:** currently closer to importance/recent-memory ranking than true goal-aware salience allocation.
- **Outcome Learning:** outcome match is manually scored by the human. The OS does not independently measure real-world outcomes yet.
- **Research authority:** source authority is a domain-based heuristic hint; it is not claim-specific epistemic authority.

### Not yet demonstrated end-to-end in a real external environment

- live OpenAI Web Search provider request
- live OpenAI reasoning/evaluator/embedding request
- live Google OAuth and Gmail/Drive/Calendar synchronization
- actual Chrome GUI installation and click-through interaction
- actual macOS Native Messaging installation
- actual Windows PyInstaller build + Chrome registry + native bridge
- signed/notarized `.app`, `.dmg`, `.exe`, `.msi`
- iPhone client
- production cloud workers

## Important remaining risks

1. **Prompt injection remains a defense-in-depth problem.** Pattern detection is useful but never sufficient. Untrusted-source isolation must remain the primary control.
2. **Web-research query privacy is imperfect.** The Executive high-risk gate is heuristic and is not a comprehensive secret/PII classifier.
3. **SSRF protection is good for an alpha but not a hardened network sandbox.** DNS rebinding/TOCTOU between validation and actual connection remains a residual risk.
4. **No encryption-at-rest layer for the local SQLite database yet.** OS account/file permissions are currently part of the trust model.
5. **No dependency lockfile/hashes.** `requirements.txt` uses minimum versions, so long-term reproducibility is not guaranteed.
6. **No automatic outcome scheduler.** `due_at` exists, but the OS does not yet autonomously request overdue outcomes.
7. **Publication dates are not reliably extracted from arbitrary HTML/PDF metadata.** Unknown date is now represented honestly as unknown/neutral freshness.
8. **Corporate/official-domain authority is heuristic.** An official corporate source can be primary for its own specification but is not automatically authoritative for comparative or normative claims.
9. **`verified` is evidence-policy status, not truth certification.** User-facing language should continue to make this distinction visible.
10. **The user's Ask text is itself sent to the remote model when an external reasoning model is enabled.** Memory filtering does not redact the user's query.

## Clean-room limitation

A completely fresh virtual environment dependency installation could not be reproduced inside the audit container because outbound package installation/DNS was unavailable. The project source runs in the existing environment and all internal tests pass, but **fresh-machine package resolution remains to be confirmed on a normal Internet-connected Mac/Windows machine**.

## Audit verdict

**GO**

- continued local development
- synthetic/non-sensitive self-use
- Developer Alpha publication with limitations stated
- further Kernel development

**CONDITIONAL**

- use with personal Google data: only after explicit OAuth setup and with local-only defaults retained
- live OpenAI research/reasoning: after a real API integration smoke test and cost/privacy confirmation

**NO-GO for now**

- production handling of identifiable clinical/patient data
- public consumer distribution described as a finished/safe autonomous OS
- autonomous irreversible external actions
- claims that `verified` means universally true
