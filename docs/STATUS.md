# Current Status — v0.7.2-alpha

## Implemented and locally validated

- local Memory / SQLite / FTS retrieval
- Goal-aware Attention
- Executive routing and cognitive mode
- always-on Base Policy + Adaptive Eval Profiles (Light / Standard / Deep / High-Stakes)
- Skills registry and execution logging
- Query Safety / privacy gate
- optional current-source Research orchestration
- Provenance / Claim / Evidence / contradiction lifecycle
- human correction and supersession
- Outcome Learning with human-accepted lessons
- Unified Attention Queue
- System Evals / cognitive-agency feedback
- local reversible Useful Automation
- proposal-only external action model
- Native Messaging bridge allowlist
- Capability Gate / Safety-Limited Velocity governance
- release tests, simulations, Red Team and archive hygiene

## Validated synthetically / locally, but not yet sufficient real-world evidence

- long-running usefulness of Attention ranking
- generalization of deterministic Executive / Adaptive-Evals routing
- source-authority heuristics across diverse topics
- real-world usefulness of Outcome Learning lessons
- human cognitive-agency benefit over weeks/months

## Requires real-device or live-provider E2E

- real OpenAI API path
- real Google OAuth / Gmail / Drive / Calendar path
- macOS signed/notarized distribution
- Windows signed distribution
- real Chrome/Edge Native Messaging across target OS versions
- iPhone client / share extension

## Explicitly not production-ready

- identifiable patient or clinical production data
- regulated enterprise deployment
- multi-user / multi-tenant use
- autonomous high-stakes medical/legal/financial decisions
- unrestricted external side effects
- irreversible actions without independent safety evidence

## Release interpretation

`Developer Alpha` means the architecture is executable and benchmarked under defined synthetic/local conditions. It does **not** mean production security, broad user validation, or proof that the cognitive model improves decisions in real-world use.
