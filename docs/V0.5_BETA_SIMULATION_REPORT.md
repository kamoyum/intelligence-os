# v0.5-beta Simulation Report

## Purpose
Test whether the current-source Research path is executable rather than only described in the design documents.

## Tests run
1. Full pytest suite.
2. Existing synthetic Knowledge Lifecycle simulation.
3. Current-source fixture simulation with an official supporting Source plus a contradictory prompt-injection Source.
4. HTTP-level simulation through `/api/ask` and `/api/research/verify`.

## Expected behaviors
- low/medium-risk current research runs automatically when enabled;
- high-risk research does not disclose the query externally without explicit per-request permission;
- search results are fetched and registered as local Provenance before Verification;
- official/primary-looking Sources receive a higher authority hint, but remain evidence rather than truth;
- prompt-injection text is flagged as untrusted evidence;
- contradicting Sources remain visible instead of being suppressed;
- Verification returns citation-ready URLs;
- research runs are auditable;
- failures/cost ceilings are explicit rather than silently replaced with model assumptions.

## Deterministic result
- current-source fixture: PASS
- HTTP auto-research routing: PASS
- high-risk permission gate: PASS
- explicit high-risk opt-in: PASS
- web-retrieval + local-memory verification scope: PASS
- citations present: PASS

These simulations use fictional Alpha rules and fake provider/fetch functions. They validate the mechanism and control flow, not the accuracy of a real search provider or arbitrary live websites.
